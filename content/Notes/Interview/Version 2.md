## 17. Technical Deep-Dive Questions

### React Hooks and State Management

**Q: Explain the difference between useState and useReducer. When would you use each?**

**High-Level Answer:** useState is for simple state management, while useReducer is better for complex state logic with multiple actions. useReducer provides more predictable state updates and better organization for complex state transitions.

**Detailed Answer:** Both hooks manage state in functional components, but they serve different complexity levels:

**useState:**

- **Best for**: Simple state values, boolean toggles, form inputs
- **Pattern**: Direct state updates with setter functions
- **Example Use**: Toggle visibility, form field values, simple counters

**useReducer:**

- **Best for**: Complex state objects, multiple related state variables, state transitions based on actions
- **Pattern**: Redux-like pattern with actions and reducers
- **Benefits**: More predictable state updates, easier testing, better organization of state logic
- **Example Use**: Shopping cart management, multi-step forms, game state management

In my university management system project, I used useReducer for managing the video call state because it involved multiple related variables (call status, participants, audio/video settings) that needed coordinated updates.

**Q: Why did you choose SVM for diabetes and Parkinson's but Logistic Regression for heart disease?**

**High-Level Answer:** Algorithm selection depends on data characteristics, feature relationships, and performance requirements. SVM handles non-linear relationships well, while Logistic Regression provides interpretable results for medical professionals.

**Detailed Answer:** My algorithm selection was based on careful analysis of each dataset's characteristics:

**Support Vector Machine (Diabetes & Parkinson's):**

- **Reason for Choice**: These datasets had complex, non-linear feature relationships
- **SVM Advantages**: Effective in high-dimensional spaces, handles non-linear patterns through kernel tricks
- **Kernel Selection**: Used RBF kernel for capturing complex patterns in medical data
- **Performance**: Achieved 77% (diabetes) and 87% (Parkinson's) accuracy

**Logistic Regression (Heart Disease):**

- **Reason for Choice**: Heart disease dataset had more linear relationships between features
- **Interpretability**: Medical professionals need to understand which factors contribute to predictions
- **Probability Output**: Provides probability scores, useful for risk assessment
- **Feature Importance**: Clear coefficient interpretation for clinical decision support

**Evaluation Process:** I tested multiple algorithms for each dataset and selected based on:

1. Cross-validation performance
2. Interpretability requirements
3. Computational efficiency
4. Domain-specific needs (medical interpretability)

This systematic approach ensures optimal algorithm selection rather than defaulting to popular choices.

**Q: Explain how you would implement authentication and authorization in a full-stack application**

**High-Level Answer:** I'd implement JWT-based authentication with refresh tokens, role-based access control, secure password hashing, and proper session management. Frontend would handle token storage and API request authentication.

**Detailed Answer:** **Authentication Flow Design:**

**1. User Registration/Login:**

- **Password Security**: bcrypt hashing with salt rounds (minimum 12)
- **Input Validation**: Email format validation, password strength requirements
- **Rate Limiting**: Prevent brute force attacks on login endpoints
- **JWT Token Generation**: Short-lived access tokens (15-30 minutes) with longer refresh tokens

**2. Token Management:**

- **Access Tokens**: Contain user ID, roles, and expiration (stored in memory/state)
- **Refresh Tokens**: Longer-lived, stored securely, used to generate new access tokens
- **Token Storage**: Avoid localStorage for security; use httpOnly cookies for refresh tokens
- **Token Validation**: Middleware for automatic token verification on protected routes

**3. Authorization Implementation:**

- **Role-Based Access Control (RBAC)**: Define user roles (admin, faculty, student) with specific permissions
- **Route Protection**: Frontend route guards and backend middleware for endpoint protection
- **Granular Permissions**: Resource-level permissions for different actions (read, write, delete)

**4. Frontend Implementation:**

```javascript
// Context for auth state management
const AuthContext = createContext();

// Protected route component
const ProtectedRoute = ({ children, requiredRole }) => {
  const { user, isAuthenticated } = useAuth();
  return isAuthenticated && hasRole(user, requiredRole) ? children : <Login />;
};

// API interceptor for automatic token attachment
axios.interceptors.request.use((config) => {
  const token = getAccessToken();
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});
```

**5. Security Best Practices:**

- **HTTPS Enforcement**: All authentication traffic over encrypted connections
- **CORS Configuration**: Proper cross-origin resource sharing settings
- **Session Management**: Automatic logout on token expiration
- **Logout Functionality**: Token blacklisting and proper cleanup

**6. Backend Security:**

- **Environment Variables**: Secure storage of JWT secrets and database credentials
- **Input Sanitization**: Prevent SQL injection and XSS attacks
- **Audit Logging**: Track authentication attempts and authorization failures
- **Password Reset**: Secure password reset flow with temporary tokens

This approach ensures robust security while maintaining good user experience across the application.

## 24. Data Science & ML Questions

**Q: How do you handle imbalanced datasets in classification problems?**

**High-Level Answer:** I use techniques like SMOTE for oversampling, undersampling majority class, class weight balancing, and evaluate using metrics like precision, recall, and F1-score rather than just accuracy.

**Detailed Answer:** Imbalanced datasets are common in real-world applications, especially in medical diagnosis where positive cases might be rare:

**Detection Strategies:**

- **Class Distribution Analysis**: Always check target variable distribution first
- **Visualization**: Use count plots and pie charts to visualize class imbalance
- **Impact Assessment**: Understand how imbalance affects business outcomes

**Addressing Imbalance:**

**1. Sampling Techniques:**

- **SMOTE (Synthetic Minority Oversampling)**: Generate synthetic examples of minority class
- **Random Oversampling**: Duplicate minority class samples
- **Random Undersampling**: Reduce majority class samples
- **Combination Approaches**: SMOTE + Tomek links for optimal results

**2. Algorithm-Level Solutions:**

- **Class Weight Balancing**: Use class_weight='balanced' in algorithms like SVM and Logistic Regression
- **Cost-Sensitive Learning**: Assign different misclassification costs
- **Ensemble Methods**: Random Forest and XGBoost handle imbalance well naturally

**3. Evaluation Strategy:**

- **Avoid Accuracy**: Can be misleading with imbalanced data
- **Precision**: Important when false positives are costly
- **Recall**: Critical when false negatives are dangerous (medical applications)
- **F1-Score**: Balanced metric for overall performance
- **ROC-AUC**: Threshold-independent performance measure

**4. Real-World Application:** In my disease prediction models, I encountered class imbalance in the diabetes dataset:

- Applied SMOTE to balance the training set
- Used stratified k-fold cross-validation
- Tuned classification threshold based on precision-recall trade-off
- Validated results using confusion matrix analysis

**5. Business Context:** In medical applications, I prioritize recall over precision because missing a positive case (false negative) is typically more dangerous than a false alarm (false positive). This influences both my sampling strategy and threshold selection.
